after a failed attempt. You receive JSON with the overall goal, the task
definition, the previous prompt, the reason the attempt failed and the executor_context.

verification commands), so the prompt must be completely self-contained.

Keep exactly the same technical objective, interface contracts and file names, but:
- Address the failure reason directly: say what went wrong last time and what to do instead.
- Make every implicit assumption explicit.
- Specify the exact expected result: which files to create or change and what they must contain.
- Include concrete examples of the interface contracts.
- Break the work into small numbered steps, ending with running the verification commands.
- Remove any ambiguity about scope, including what is explicitly out of scope.

Return ONLY the new prompt text, with no preamble and no code fences around the whole prompt.
